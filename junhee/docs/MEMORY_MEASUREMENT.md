# 분석 메모리 측정 기록 (한국은행 원표 외부 링크)

## 배경
- 2026-10-06 커밋 `575c887`: 한국은행 가격 원표(`_read_bok`)를 `keep_links=False`로 읽도록 수정.
- 커밋 메시지 기록: 외부 링크 XML(약 30MB) 때문에 예시 분석이 약 466MB까지 올라 512MB Render 인스턴스가 종료됨 → 수정 후 최대 약 215MB, 값은 동일.
- 당시 측정 스크립트·원시 로그는 남아 있지 않아, 같은 시나리오로 다시 측정했다.

## 재측정 (2026-11-10)
- 스크립트: `junhee/scripts/measure_memory.py` (Portfolio AXPORT 폴더에서 실행)
- 시나리오: 테스트와 같은 방식으로 예시 파일 `기업데이터_예시1_한울메모리.xlsx`(HS 854232, 미국) 업로드·분석. 외부 API 키 없음, 임시 DB, 분석 기준일 2026-10-06 고정.
- 모드: `keep_links`(수정 전 동작을 재현: 외부 링크까지 읽음) / `current`(현재 코드). 모드마다 새 프로세스.
- 측정값: Windows `PeakWorkingSetSize`(프로세스 최대 물리 메모리)
- 환경: Windows 11 Pro, Python 3.14.7, openpyxl 3.1.5(`requirements.txt` 기준 가상환경)

| 실행 | keep_links (수정 전) | current (현재) | 분석 결과 해시 |
|---|---:|---:|---|
| 1회 | 466MB | 221MB | 두 모드 동일 (63bd258dfc361111) |
| 2회 | 466MB | 220MB | 두 모드 동일 |

분석 전(앱 로드 후) 최대 메모리는 두 모드 모두 65MB.

## 해석과 한계
- 수정 전 466MB는 커밋 기록과 같고, 수정 후는 220~221MB로 기록(215MB)과 약 5MB 차이.
- 로컬 Windows 측정이라 Render(리눅스, gunicorn) 프로세스의 수치와 측정 방식이 같지 않다. 절대값보다 "같은 조건에서 수정 전후 비교"로 읽어야 한다.
- 결과값이 같다는 것은 handoff 문서의 국가별 항목·점수 해시 비교로 확인했다.
